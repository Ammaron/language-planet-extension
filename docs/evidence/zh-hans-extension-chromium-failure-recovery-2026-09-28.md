# Chinese extension failure and recovery in a browser

Date: 2026-09-28. Scope: the built local Chrome extension loaded in bundled headless Chromium with an isolated profile, a loopback page, and a mock API. No Langsly account or production curriculum was accessed.

The [smoke script](../../test/browser/zh-sync-chromium-smoke.cjs) loaded `dist/chrome`, obtained a synthetic Chinese-to-Spanish word from a mock successful sync, and let the actual content script request mock occurrence validation. The page showed `hola，朋友。` with one `.lp-vocab-word` element. The mock then returned HTTP 503 for the next vocabulary sync, initiated through the extension popup. The page returned to `你好，朋友。` with no replacement element; storage contained zero words, zero matchable words, no last-sync time, and `syncStatus='failed'`. A subsequent successful popup sync restored the mock-approved match and `syncStatus='success'`. The fresh-profile run reported three vocabulary requests and two occurrence-validation requests.

Visual evidence: [before failure](zh-sync-before-failed-sync.png), [after failure](zh-sync-after-failed-sync.png), and [after recovery](zh-sync-after-recovery.png). The screenshots were inspected against the DOM and storage assertions. The test completed with exit code 0. The script accepts `LANGSLY_PLAYWRIGHT_MODULE` and `LANGSLY_CHROMIUM_EXECUTABLE` for environments where Playwright and Chromium are bundled outside the project.

The Playwright CLI package was unavailable because this environment denied the npm registry request, so the script used the workspace's bundled Playwright library. An isolated headless installation of Google Chrome did not expose an extension service worker within the 20-second timeout; that attempt is inconclusive. This Chromium result verifies local browser behavior of the built package only. Installed Chrome and Firefox, real reviewed production Source Forms, actual provider decisions, native-reviewed Chinese interface copy, and store publication remain open.

## September 29 rerun

The current extension was rebuilt and the smoke was rerun using the cached Chromium executable. A fresh profile initially failed before any mock API request: the worker's asynchronous startup migration replaced the test's loopback API address with its normal default. The smoke now waits for startup configuration to settle before setting its mock address and emits configuration/request diagnostics on an initial-sync failure. With both a fresh and a previously used isolated profile, the built extension passed the Chinese match, failed-sync clearing, and recovery flow (three mock vocabulary requests, two mock occurrence-validation requests). The full extension release command also passed 97 unit tests, Chrome/Firefox artifact checks, and Firefox lint with zero errors, notices, or warnings. A separate installed headless Google Chrome attempt again timed out before exposing an extension service worker, so Chrome acceptance remains unverified. No production vocabulary, real provider, account, or store package was used.
